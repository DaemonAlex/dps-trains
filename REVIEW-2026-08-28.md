# Code review — branch `trains-solid-20260828` (2026-08-28, pre-ship)

High-effort review of the "one schedule physics" rework: 10 findings,
**7 CONFIRMED / 3 PLAUSIBLE / 0 refuted**. DO NOT push/PR this branch until
these are addressed. The branch is live on the dev box and is still a net
improvement over main, but the transition seams below undo part of the fix.

**Dominant theme:** ghost/materialised state now lives in four places
(`private.*`, the ghost tables in CTrain, `headwayState` in main.lua, the
entity state bag) and every transition between the two worlds drops state.
The right fix is a state handover at the two boundaries — `RegisterEntity`
(ghost → real) and `Remove` (real → ghost) — not more flags.

## Findings

1. **Dwell handover broken both ways** (CTrain.lua ~550 / UpdatePosition).
   Ghost dwelling → materialises: `RegisterEntity` commands full
   `trainSpeed = self.speed` (lurch off the platform, slam-stop, doors reopen,
   serves a SECOND full dwell). Materialised dwelling → de-materialises:
   ghost path reads only `ghostDwellUntil`, so remaining `private.dwellUntil`
   is abandoned — train departs instantly. Observed trains still lose schedule
   vs the ghost fleet — the exact drift this branch exists to eliminate.
   *Fix: on RegisterEntity, if ghostDwellUntil active → set speed 0, doors,
   private.dwellUntil = remaining ghost dwell, clear ghost entry. On Remove,
   if private.dwellUntil active → ghostDwellUntil = it, ghostServed = station.*

2. **Headway holds don't survive transitions** (main.lua ~260). Hold form
   (state-bag 0.0 vs SetGhostHold) chosen once at onset; RegisterEntity/Remove
   never convert it. Held ghost materialises → drives at line speed into the
   dwelling leader. Held real train de-materialises → ghost advances through
   the train ahead (the exact pass-through the hold prevents).
   *Fix: convert the hold at both boundaries; or re-evaluate holds every tick
   instead of only on the blocked/unblocked edge.*

3. **Client slam-stop + player-driven trains frozen** (client/main.lua ~393).
   `value <= 0.5 → SetTrainSpeed(0.0)` slam-stops a 28 m/s follower on a
   headway hold (holds send 0.0 with no braking ladder). And the headway pass
   lacks the `isPlayerDriven` guard every other pass has — a player driving
   legally gets frozen. *Fix: headway should command a staged brake (or the
   client should ramp when speed drops from high value), and skip
   player-driven trains in the headway pass.*

4. **skipStations not honored by the braking ladder** (CTrain.lua ~934).
   `getClosestStation` doesn't filter skips, so materialised trains still run
   the full 500m ladder for Wind Farm every lap (the exact crawl the skip
   config was added to remove). *Fix: filter skips inside getClosestStation
   (single source), which also fixes the 8m trigger edge case.*

5. **Metro variation fallback leaks 12 models** (client/main.lua ~351).
   Metro actually spawns vanilla variation 27 on b3258 (configs/metro.lua
   computes 24+3; the "31" claim in README/data is wrong); 27 is not in
   data/trains.lua (28–31 only) → every metro creation loads ALL
   trainModels and the release path (`if variations[data.variation]`) never
   frees them. *Fix: add 27→{metrotrain} to data/trains.lua generation, and
   free the fallback list after creation.*

6. **Arrival board blind to ghost dwell; ETAs undercharged** (main.lua ~1116).
   Status reads only `private.dwellUntil`; per-stop charge is flat 30s while
   real ghost stops cost regulated dwell + 25s penalty; `stopsBetween` counts
   skipped Wind Farm. *Fix: consult GetGhostDebug() for status/ETA, charge
   regulated dwell + penalty, and filter skips in the stopsBetween loop.*

7. **Headway resume can skip re-braking** (main.lua ~277). Resume no longer
   refreshes `appliedZoneSpeed`, so a train released inside a braking band
   sees a stale match and the ladder never re-commands the brake — worst-case
   geometry crosses the platform at 28 m/s and blows through the stop.
   *Fix: expose a setter for appliedZoneSpeed (or clear it) on resume.*

8. **ghostServed never cleared; ghost tables leak** (CTrain.lua ~695).
   Ghost-served station X, materialised around the loop, re-ghosted before X
   → next lap's ghost skips X's dwell. `Train:Remove` never deletes
   ghostStepClock/ghostDwellUntil/ghostServed/ghostHold entries and ids
   increment forever. *Fix: clear ghost tables in Remove(); clear ghostServed
   on materialisation.*

9. **onResourceStop carriage walk uses deleted engine** (client/main.lua
   ~1067). Fetches successors from data.entity after deleting it in
   iteration 1 → carriages 2..N never walked; masked today only by the
   blanket type-14 sweep. *Fix: collect all handles before deleting, or walk
   GetTrainCarriage(carriage, 1).*

10. **atStationNode nil-order + direction=false degradation** (CTrain.lua
    ~871). `ahead = sn - self.currentNode` computed BEFORE the `if sn`
    nil-guard (a station entry lacking .node crashes Train:Update outside the
    pcall); and the 0..1 approach window assumes direction=true — the
    cablecar's ping-pong return leg (direction=false) degrades to exact-node
    match. *Fix: guard sn first; use direction-aware ahead
    (`direction and sn-node or node-sn`).*

Cleanup noted but uncapped: station-list+skip scan hand-rolled in five
places (consolidate); `Train:SetDwellUntil` and `physHoldState` now dead;
`SPEED_ZONES[0] = {}` encodes line speed in table presence.
